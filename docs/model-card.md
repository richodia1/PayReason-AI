# Synthetic demonstration model

## Intended use

Demonstrate an end-to-end payment-risk review and explanation workflow in PayPal Sandbox. This is **not a validated fraud detector**, an academic benchmark on real fraud, or a production payment-decision system. Every assessment starts on HOLD. A human must explicitly RELEASE before capture or BLOCK before void.

## Data provenance

All 12,000 rows are generated by `ml/training/train_demo.py`, seed 20261106. There are no customer records, downloaded datasets, or proprietary training examples. Five inputs describe a simulated payment: amount relative to historical average, account age in days, transaction count during the previous hour, new-device flag and cross-border flag. The UI supplies editable sample signals, not verified device telemetry or PayPal-derived fraud signals.

Labels are Bernoulli samples from this deliberately specified simulation:

```text
logit = -4 + 0.5 * amount_ratio - 0.0008 * account_age_days
        + 0.5 * transactions_last_hour + 1.4 * new_device + 0.6 * cross_border
P(synthetic positive) = sigmoid(logit)
```

The model therefore learns a simulated relationship. Good metrics on this distribution do not establish effectiveness on real payments. There is no identity inference, demographic feature, real-world causality claim or proof that a payment is fraudulent.

## Training and evaluation

Stratified fixed-seed split: 7,200 training, 2,400 validation, 2,400 test rows. StandardScaler is fitted only on training rows, inside a scikit-learn pipeline with logistic regression. There is no resampling, test-data tuning or external dataset license dependency. The fixed 0.25 and 0.60 band thresholds are illustrative, not optimized business thresholds.

The generated `ml/evaluation/synthetic-report.json` records exact class counts, dataset hash, library version, ROC AUC, average precision, Brier score and positive prevalence for each held-out split. Report these only as **synthetic experiment results**.

```sh
services/ai-service/.venv/bin/python -m pip install -r ml/training/requirements-demo.txt
services/ai-service/.venv/bin/python ml/training/train_demo.py
```

The script exports safe JSON coefficients to `services/ai-service/app/demo_model.json`. Runtime inference needs no pickle or scikit-learn installation. The committed artifact allows a clean Docker build without retraining. Training dependencies are separate from runtime dependencies.

## Explanation method

Each contribution is `coefficient * (value - training_mean) / training_scale`, in log-odds units. Adding all contributions to the intercept and applying sigmoid reconstructs the score. This is exact for this linear model. It is not SHAP, a counterfactual explanation, or a causal attribution. The explanation text is a deterministic summary of the largest contribution, not an LLM assertion. Scores describe the learned synthetic distribution, not calibrated real-world fraud probability.

## Before any production use

Obtain representative, lawfully sourced labelled payment data; independently validate features, temporal splits, leakage, calibration, false-positive cost, drift and fairness. Replace manual scenario inputs with authoritative signals. Add governance, access controls, privacy/retention policies, monitored model versions and institution-approved thresholds. Do not reuse these coefficients to make real financial decisions.
